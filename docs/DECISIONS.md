# Implementation decisions

- **One workflow:** employee search → annual salary edit → same-filter currency summaries. Scope and acceptance criteria were committed before implementation (`a1cd326`).
- **Relational persistence:** hosted Cloudflare D1 is durable SQLite, separate from Worker deployments; local development and tests use better-sqlite3. Sites provisions D1 and applies schema-only Drizzle migrations. This avoids ephemeral filesystem storage and a second service.
- **Same Express application:** local Node HTTP server and the official Cloudflare Node HTTP adapter share routing, validation and SQL services. React assets and API ship as one Worker. Reference: https://developers.cloudflare.com/workers/tutorials/deploy-an-express-app/ (checked 2026-11-23).
- **No mixed-currency totals:** all four currencies have two minor digits. Each summary stays in its original currency, and every period is annual base salary. The directory also shows a USD amount from fixed fictional rates dated 15 Nov 2026 (INR 0.012, EUR 1.08, GBP 1.27). That figure is display-only. Insight charts use the same rule: the dashboard shows two headcount charts only, so salary amounts stay on the currency cards and are never mixed on one axis.
- **Timebox:** start 11:39 IST; aim for deployed complete workflow by 15:39, submit by 17:39; buffer to 18:39. Finish sooner if validation and deliverables are complete.
- **UI method:** The dashboard is shadcn/ui on a graphite ledger. Teal remains the save action and focus ring. `/` is the pay insight and `/employees` is the directory. Both are reached from the sidebar. Currency totals are cards on the insight. The employee table fills its own page, with the ID beside the name and paging in the table footer. Name search does not change the insight. unslop by Damir Sokolovsky (https://github.com/heydamir/unslop) set that direction.
- **CSV import and toasts:** One CSV upload may create up to 10,000 employees. Success and failure messages for import, export, add-employee and remove-employee appear in a top-right toast rather than an in-page alert.
- **Employee removal:** DELETE `/api/employees/:id` removes the employee and their salary history after a confirmation dialog in the directory or detail view.
- **Author badge:** The server injects a floating Made by chetangehlot badge into the HTML shell outside `#root`, with a restore script if the node is removed from the DOM.

Employee numbers above the seeded range are issued monotonically. SQLite owns salary history writes so a failed history insert rolls back the raise. CSV uploads commit 100 rows at a time and use one receipt per file and offset to support retries.

The requested Vercel deployment uses Turso libSQL for persistent relational storage. This preserves existing SQLite queries, constraints and triggers. The custom-domain candidate is salary.chetangehlot.com. Vercel serves static assets directly, while API requests use the shared Express app. Migration and seed preparation are explicit release operations.
